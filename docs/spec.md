# DocScope 技术规格

> 状态：设计规格，尚未实现。范围与决策依据来自 [CONTEXT.md](CONTEXT.md)、[ARCHITECTURE.md](ARCHITECTURE.md)、[ADR](adr/) 和 [design.md](design.md)。`M1/M2/M3` 是秋招展示版的递进交付；`M4/M5` 为后续迭代。标为 **Assumption** 的内容须在 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) 所列阶段冻结，不能据此宣称已有能力。

## 1. System Overview

DocScope 是面向单个本地使用者的英文多文档知识分析系统。它计划将文本型 PDF、Markdown 与离线评测文章转换为可追溯 Chunk，以 Dense 与 BM25 检索、RRF 融合和本地 Cross-Encoder 重排提供证据。M3 的单 LangGraph Agent 在有界预算内按证据决定下一次查询，给出有引用的回答或明确拒答；React/FastAPI 提供 Web 入口与 SSE 展示。参考答案和证据标注只供离线 Evaluation 使用。

## 2. Goals

1. 在 M1 交付可验证的“上传 → 索引 → Dense 检索 → 回答 → 引用 → 评测”基础闭环。
2. 在 M3 交付 Hybrid、有界动态多跳、拒答、SSE 和公平对照评测，形成秋招展示版。
3. 让引用能回溯到实际检索的原文 Chunk；区分“引用 ID 合法”与“内容支持结论”。
4. 保存逐题质量、轨迹与成本记录；只有封存测试集结果支持时才宣称效果提升。
5. 将远程 LLM 调用总费用控制在 100 元人民币以内，并提供可复现的本地运行与评测步骤。

## 3. Non-goals

M3 不交付多轮会话记忆、中文检索能力、文档版本历史、生产级权限/多租户/高并发、扫描件 OCR、复杂 Office/表格/图片解析、实时联网搜索、企业知识自动同步、Multi-Agent 或 GraphRAG。M4 才引入会话级短期记忆；M5 才要求 Docker Compose 与完整交付打磨。M1 的 Dense 闭环不得被描述为已经完成 Agentic RAG。

## 4. User Stories

1. 作为本地使用者，我希望上传英文文本型 PDF 或 Markdown，以便纳入可检索材料。
2. 作为本地使用者，我希望看到每份文档是否完成索引或失败，以便知道哪些材料可用于问答。
3. 作为本地使用者，我希望重传同一文档时替换旧索引，以便结果不重复或过期。
4. 作为本地使用者，我希望删除文档后它不再出现在检索结果中，以便移除无效材料。
5. 作为本地使用者，我希望对已索引文档提出英文事实问题，以便获得有原文依据的回答。
6. 作为本地使用者，我希望比较多份文档，以便看清各自证据支持的异同。
7. 作为本地使用者，我希望点击引用查看文档名称、页码或章节与原文片段，以便核对结论。
8. 作为本地使用者，我希望旧文档被替换或删除时看到引用失效提示，以免误把新材料当成旧证据。
9. 作为本地使用者，我希望在材料不足时看到明确拒答，以免得到虚构结论。
10. 作为本地使用者，我希望复杂问题能根据第一跳新发现的事实继续检索，以便回答依赖中间事实的问题。
11. 作为本地使用者，我希望看到回答流和简要检索阶段，以便了解当前运行及最终证据。
12. 作为本地使用者，我希望失败的上传或问答有可理解的错误状态，以便重试或修正输入。
13. 作为项目评测者，我希望在冻结数据与配置上运行 Dense、Hybrid、Rerank、单轮规划和动态 Agent 对照，以便审查各阶段效果与成本。
14. 作为项目评测者，我希望参考答案与证据标注不进入在线检索和 Prompt，以便避免 Ground Truth 泄漏。
15. 作为项目评测者，我希望分别查看文章级和支持事实片段级结果，以免把找到文章误认为找到可引用证据。
16. 作为项目评测者，我希望核对真实依赖前跳的新查询、拒答和错误拒答，以便判断 Agentic 能力是否成立。
17. 作为后续 M4 使用者，我希望在同一会话内追问并切换会话，以便延续讨论，同时让新事实仍接受文档检索验证。

## 5. Functional Requirements

以下 ID 用于需求、测试与验收追溯。每条均描述外部可观察行为；具体参数和接口路径由对应阶段冻结。

| ID | 阶段 | 要求 | 验证方式 |
|---|---|---|---|
| FR-01 | M1 | 接收英文文本型 PDF/Markdown；解析成带来源位置的 Chunk，完成本地 Embedding 与 Dense 索引。 | 固定双格式样例上传后可检索，返回 Chunk 文本与正确来源位置。 |
| FR-02 | M1 | 文档列表展示导入状态；只有完整索引成功的文档可用于问答。 | 分别注入成功、解析失败、Embedding/索引失败，核对可见状态和检索结果。 |
| FR-03 | M1 | 同一逻辑文档的重复上传不增加重复 Chunk；重传内容变化时替换旧索引，删除后旧 Chunk 不再可检索。 | 比较重传前后 Chunk 集合，并在替换/删除后查询旧文本。 |
| FR-04 | M1 | 接收一个独立英文问题，执行 Dense 检索并返回回答或证据不足结果。 | 固定可回答和无证据问题，检查回答依据或拒答，不允许编造引用。 |
| FR-05 | M1 | 每条引用指向本次实际检索的 Chunk，并提供文档名、原文片段及可用页码/章节；来源失效时明确提示。 | 对照检索记录与 UI 引用；替换/删除来源后检查失效提示。 |
| FR-06 | M1 | 离线评测能在冻结输入上运行 Dense Baseline，保存逐题配置、检索结果、答案与错误。 | 同配置重复运行，核对题目集合与输出字段。 |
| FR-07 | M2 | 在同批 Chunk 上执行 Qdrant 原生全文 BM25 与 Dense 检索，RRF 融合、去重并按配置启用本地 Cross-Encoder 重排。 | 切换 Dense-only、Hybrid、Hybrid+Rerank 三组，对照来源 ID、排名和输出。 |
| FR-08 | M2 | 限制每路候选、重排候选与最终证据长度，并分别记录文章级和事实片段级检索结果。 | 配置边界值运行，检查输出不超限、指标分母与映射失败记录。 |
| FR-09 | M3 | 单 Agent 根据问题和已检索证据规划后续查询；人工审查样本中至少一例第二跳查询必须利用第一跳新事实。 | 审查逐跳查询、返回证据、缺失事实与最终答案轨迹。 |
| FR-10 | M3 | 程序强制检索/模型/上下文预算、重复查询与无新证据停止；LLM 评估缺失事实；必要证据仍不足时拒答并记录原因。 | 对充分、缺失、重复、无新证据和预算耗尽样本分别核对停止原因与调用上限。 |
| FR-11 | M3 | 引用 ID 由程序校验；回答不得引用未检索 Chunk，引用支持性另经评测核查。 | 注入不存在或未返回的 ID，确认不会出现在成功答案中；人工核查支持性样本。 |
| FR-12 | M3 | SSE 至少发送 `stage`、`token`、`citation`、`done`、`error` 类型；事件可关联 `run_id` 与本轮消息；成功和已捕获失败有明确终态。 | 客户端消费正常流与故障流，检查事件关联、终态和 UI 错误提示。 |
| FR-13 | M3 | Web 展示简要检索轨迹：轮次、查询、检索完成、引用集合与停止原因，不展示模型私有推理链。 | 对照保存的 Run 轨迹与页面展示内容。 |
| FR-14 | M3 | 离线评测隔离标签，运行 A–E 消融、实际效果与相近预算的 D/E 对照，保存逐题质量、延迟、Token、调用量与费用。 | 审查配置、输入集合、逐题记录及聚合报告；检查无法严格等预算时的差异披露。 |
| FR-15 | M3 | 用 MultiHop-RAG 的 `null_query` 和自建无证据问题评估适当拒答，同时在可回答题上评估错误拒答。 | 核对不同分母、逐题预测和错误案例。 |
| FR-16 | M4 | 会话级历史支持近期窗口、较早历史摘要与追问改写；每轮重置暂态，事实仍经检索验证。 | 多轮指代、话题切换、长历史及跨轮污染样本回归。 |
| FR-17 | M4 | 可新建/切换/删除会话；删除会话时消息和 Checkpoint 可清理。 | 重新打开会话与删除后查询，检查连续性和清理结果。 |

## 6. Non-functional Requirements

| ID | 阶段 | 可验收约束 |
|---|---|---|
| NFR-01 | M0 起 | 固定数据/模型/配置版本与评测样本 ID；封存测试集不用于调参；逐题原始结果可对应汇总指标。 |
| NFR-02 | M1 起 | 文档、Chunk、Evidence、Citation 和 Run 之间可沿 ID 与源位置追溯；替换/删除后旧内容不再参与检索。 |
| NFR-03 | M1 起 | 上传格式、大小和路径受后端校验；外部文档按不可信数据处理；LLM 凭据仅在后端配置，公开产物不含凭据或保密材料。 |
| NFR-04 | M2 起 | 检索和重排记录逐题耗时；M3 再记录模型调用、Token、检索轮数、费用与预算超限/失败。暂不设未经测量的固定毫秒目标。 |
| NFR-05 | M3 | 每次 Run 受明确的调用、轮数和上下文上限约束；达到上限后返回有记录的停止结果，不无限重试。具体上限是 M3 阶段关口。 |
| NFR-06 | M0–M3 | 远程 LLM 总费用不超过 100 元人民币；先测开发集单题成本，再冻结回答/Agent 分层子集与调用上限。 |
| NFR-07 | M3 | 不把子集 Answer/Agent 结果称为全量成绩，不把文章级命中称为支持事实片段命中，不在未提升时声称优于基线。 |
| NFR-08 | M1–M3 | 本地运行步骤和评测命令可由新环境按锁定配置重放固定演示路径；Docker Compose 是 M5 目标。 |

## 7. User Interaction Flows

### 7.1 文档导入、重传与删除 [M1]

- **正常路径**：用户选文件 → 后端校验 → 显示导入中 → 解析/分块/Embedding/索引 → 状态变为可用 → 问答可检索到该文档。
- **边界路径**：同内容重传不增加重复 Chunk；内容变化重传替换旧内容；删除后旧内容和旧引用不可用。
- **错误路径**：不支持的格式、空内容、不可解析文件或摄取阶段失败时显示可诊断错误；失败文档不得被标记为可用，也不得把未完成的 Chunk 当作已发布索引。

### 7.2 单轮问答与引用 [M1]

- **正常路径**：用户输入独立英文问题 → Dense 检索 → 生成回答 → 页面展示来源片段和可用页码/章节。
- **边界路径**：多篇文档均相关时保留多个来源；已替换或删除的旧引用显示失效。
- **错误路径**：空问题被拒绝；没有足够文档证据时返回证据不足结果；远程 LLM 失败时显示失败，不把部分结果标为完成。

### 7.3 动态多跳与流式展示 [M3]

- **正常路径**：问题 → 规划缺失事实 → 检索 → 评估 → 如需补事实则依据新证据再检索 → 回答与引用；SSE 发送阶段、文本、引用及 `done`。
- **边界路径**：已充分则提前停止；重复查询、无新证据或预算耗尽则停止；必要证据仍缺失则拒答，并显示停止原因。
- **错误路径**：检索、模型或流式处理失败时发送可关联的 `error`（连接仍可用时）并显示错误；连接中断的恢复/重试语义尚未冻结，客户端不得将未收到完成信号的回答标为成功。

### 7.4 离线评测 [M0–M3]

- **正常路径**：冻结语料/问题/配置 → 运行 Dense 基线 → 增量运行 Hybrid、Rerank、单轮规划、Agent → 计算分层指标并保存逐题结果。
- **边界路径**：无证据 `null_query` 不进入召回分母；无法可靠映射 `fact` 的样本单列；回答/Agent 仅跑预先固定的分层子集。
- **错误路径**：数据版本、证据映射或费用预算不满足评测合同，评测应明确失败或标记该题不可计分，不静默归入模型错误或有效成绩。

## 8. Data Model

这是跨组件的数据合同，不预设数据库表或类设计。

| 概念 | 必需信息与约束 |
|---|---|
| Document | 稳定 `document_id`、标题、来源类型与位置、内容哈希、索引版本、导入状态；重传属于同一逻辑文档的替换。 |
| Chunk | `chunk_id`、所属 `document_id`、原文、索引版本、可用页码/章节或其他源位置；不同内容不可被旧引用静默指向。 |
| Evidence | 某次检索实际返回的 Chunk 身份、文本、来源、检索阶段及排名/分数；只把实际检索结果交给生成和引用。 |
| Citation | 指向该 Run 实际 Evidence 的可校验 ID 与展示所需来源信息；失效状态与内容支持性分开处理。 |
| Retrieval Round [M3] | 本轮查询、返回 Evidence ID、缺失事实/覆盖判断、是否继续及原因；具体结构化输出尚待 M3 冻结。 |
| Run | `run_id`、独立问题、阶段状态、轮次/调用/耗时/费用、答案或拒答、停止或错误原因、引用集合。M1 可只记录单轮子集。 |
| Evaluation Item / Result | 固定样本 ID、问题类型、离线参考答案和标注、所属划分、配置版本、逐题预测与指标输入；参考标注不得流入在线组件。 |
| Conversation [M4] | `thread_id`、消息、近期上下文、摘要与会话元数据；与当前 Run 暂态分离。 |

**Assumption**：文档状态和轻量元数据先用 SQLite；导入状态的具体枚举、ID 生成与原子替换机制由 M1 冻结。评测 `fact` 到 Chunk 的匹配规则及跨 Chunk 事实处理由 M0 冻结。

## 9. Component Boundaries

- **Web ↔ API**：Web 只发送用户操作并展示状态、回答、引用、轨迹；业务判断由后端负责。M3 使用与 POST 兼容的 SSE 客户端读取方式。
- **API ↔ Ingestion**：API 负责输入校验和对外状态；Ingestion 负责解析、分块、Embedding 和索引发布。
- **Agent ↔ Retrieval Engine**：Agent 决定何时、为何、以什么查询检索；Retrieval Engine 只返回排序后且可追溯的 Evidence，不决定是否继续。
- **Ingestion/Retrieval ↔ Qdrant**：同一 Chunk 身份贯穿 Dense、BM25、RRF、Reranking；不引入独立 BM25 存储，遵守 [ADR 0001](adr/0001-qdrant-hybrid-index.md)。
- **Online ↔ Evaluation**：在线侧可使用文章正文，不能读取参考答案、支持 `fact` 或人工结论；评测器使用同一摄取/检索配置做对照，遵守 [ADR 0004](adr/0004-evaluation-isolation-and-fair-comparison.md)。

## 10. State Management

- **导入状态 [M1]**：可区分处理中、可用和失败；只有索引完整后对问答可见。替换/删除期间的可见性必须满足 FR-03，具体事务机制是阶段未决项。
- **Run 状态 [M1/M3]**：每次问题有独立 `run_id`。M3 逐轮更新计划、Evidence、缺失事实、预算消耗与停止原因；成功回答、拒答和失败须可区分。不同 Run 的暂态不得相互污染。
- **SSE 状态 [M3]**：`stage`、`token`、`citation` 为过程事件，`done` 表示完成，`error` 表示已捕获失败；UI 仅在完整完成后显示成功。断连/重试协议仍是开放问题。
- **会话状态 [M4]**：按 `thread_id` 恢复；保存完整历史不等于把全部历史输入 LLM。近期窗口与滚动摘要只用于理解意图，当前事实重新检索；每轮重置检索计划和 Evidence 暂态。

**Assumption**：最多三轮检索和基于 Token 阈值触发摘要只是候选默认值，不是本规格固定参数。

## 11. Persistence Rules

1. 原始上传文件及必要解析产物保存在本地文件存储；Qdrant 保留可检索 Chunk、Dense 向量、M2 BM25 全文索引与来源元数据。
2. 导入状态与轻量元数据持久化。**Assumption**：采用 SQLite；具体职责、原子替换和清理机制在 M1 验证。
3. 重传替换不能留下可检索的过期 Chunk；删除后旧 Chunk 不可检索。历史引用若对应来源已失效，保留可识别的失效状态，不转向新内容。
4. M3 保存足以审查检索轨迹、停止原因、引用、逐题结果和费用的记录；不得保存模型私有推理链或公开敏感凭据。保留时长尚未决定，不列为 M3 验收指标。
5. 离线参考答案、标注和人工评语与在线索引/Prompt 隔离；公开仓库仅放许可允许的数据、脱敏配置和报告。
6. M4 才持久化会话消息与 Checkpoint；消息表和 Checkpointer 职责边界仍待确定。删除会话时两者均须可清理。

## 12. Input Validation

| 输入 | 必须校验的边界与可见结果 |
|---|---|
| 上传文件 [M1] | 只接受文本型 PDF/Markdown；检查格式、配置的大小上限和路径安全。空文件、不可解析文件或超限文件不能进入可用状态。具体字节上限由 M1 Issue 冻结，并测试边界值与超限值。 |
| 文档重传/删除 [M1] | 仅操作可识别的逻辑文档；重复请求不得产生重复可检索 Chunk；不存在的文档不能被报告为成功删除或替换。具体 HTTP 状态码由 API Issue 冻结。 |
| 问题 [M1/M3] | 空白问题不得触发检索或 LLM 调用；问题长度与上下文上限由阶段配置控制，超限时明确返回输入错误。英文是验收范围，不要求实现自动语言识别或拒绝非英文文本。 |
| Agent 结构化输出 [M3] | 查询、缺失事实和引用 ID 必须通过结构校验；不合格输出不能触发无限重试，也不能成为成功引用。 |
| 外部文档内容 [M1 起] | 文档文本按数据处理，不能覆盖系统指令；可用含伪指令的公开样例验证。 |

## 13. Error Handling

| 情况 | 外部行为 | 验收检查 |
|---|---|---|
| 上传校验失败 | 返回可理解的输入错误，文档不进入可用列表/索引。 | 不支持格式、空文件、超限与不安全路径各有失败结果。 |
| 解析/Embedding/索引失败 | 显示失败状态，问答不检索未完成内容；允许后续按已确定的重传路径恢复。 | 故障注入后查询不可命中失败导入的 Chunk。 |
| 检索无证据或必要事实缺失 | 明确证据不足；不输出虚构引用。 | 无证据问题和缺一跳证据问题的结果可区分于系统故障。 |
| 预算耗尽、重复查询、无新证据 [M3] | 停止循环，记录原因；若必要事实仍缺失则拒答。 | 逐题轨迹无超限调用且有停止原因。 |
| LLM、Reranker 或流式处理失败 | 返回失败而非成功答案；SSE 连接仍可写时发出 `error`，前端提示失败。 | 故障流无虚假的 `done` 成功结果。 |
| 旧引用来源被替换/删除 | 展示引用失效，不能跳到不相同的新 Chunk。 | 保留替换前的回答结果，替换后再次打开其引用，检查状态和源位置；不要求 M1 提供会话历史。 |
| 离线评测标签/映射异常 | 单列不可计分或使运行失败，不把数据问题算作模型漏检。 | 故意缺失标注/无法映射时检查报告分类。 |

## 14. Accessibility Requirements

以下只覆盖已规划的上传、问答、引用、轨迹和错误界面，不新增产品功能。

1. 所有上传、提问、引用查看和删除控件可仅用键盘操作，且焦点位置可见；以键盘走完 M1 主路径作为验收。
2. 表单控件有可读取的名称；校验错误与对应输入或操作关联，不能只用颜色表示。
3. 回答、索引状态、SSE 完成/错误可被辅助技术获知；连续 Token 不应使屏幕阅读器对每个字符重复播报。具体播报策略在 Web Issue 中验证。
4. 引用和轨迹文本在键盘与屏幕阅读器下可辨认来源、页码/章节和失效状态；装饰性图标不能成为唯一状态提示。

## 15. Test Strategy

**首选测试接缝**：以公开的 Web/API 行为和离线 Evaluation 命令作为主要集成测试入口，使用固定的公开英文 PDF/Markdown、问题与预期来源；对 Qdrant 和远程 LLM 边界使用可控测试配置或替身，以验证故障和预算行为。针对分块/映射等纯规则补少量必要单元测试，不编写与实现逐行镜像的测试。当前仓库尚无业务代码或既有测试可复用。

| 阶段 | 测试组 | 通过条件 |
|---|---|---|
| M0 | 数据适配、标签隔离、版本/划分与费用试运行 | 样本 ID/分割可复现；在线索引/Prompt 不含答案与证据标注；单题成本可记录。 |
| M1 | 上传、状态、失败、重传、删除、Dense 问答与引用端到端 | 固定样例的原文位置正确；重复/替换/删除满足 FR-03；错误不会产生可用索引；Dense Baseline 可复跑。 |
| M2 | 三种检索配置、候选预算与指标映射 | 同批 Chunk 和开发集上可切换；文章级/片段级分别计分；逐题延迟与错误案例可输出。 |
| M3 | 真实依赖型多跳、停止/拒答、引用校验、SSE 正常/故障、成本与公平对照 | 第二跳能追溯前跳新事实；无超限或虚构引用；SSE 终态正确；实际与相近预算对照逐题可审查。 |
| M4 | 多轮指代、话题切换、长历史、会话删除 | 查询改写仍检索文档；暂态不串轮；消息与 Checkpoint 可清理。 |

评测指标包括文章级 Recall@K/All-Evidence Recall@K、片段级支持事实覆盖、答案准确性、引用合法率与支持率、适当/错误拒答率，以及延迟、Token、调用量、轮数和费用。`null_query` 不进入有证据召回的分母；无法可靠映射 `fact` 的样本单列。开发集用于调参，封存测试集仅在方案冻结后用于最终报告。MultiHop-RAG 用于总体比较；人工审查依赖型样本验证动态第二跳。测试策略不要求预设指标提升。

## 16. Deployment Model

- M1–M3：单用户、本地运行的 React 前端、FastAPI 后端、Qdrant 和本地源文件；Embedding 与 Reranker 在本地推理，LLM 通过远程 API 调用。具体 Provider、模型、版本及凭据配置须在 M0 验证。
- M3：提供锁定依赖/模型配置、本地启动步骤、评测步骤和固定演示路径；不要求生产级高可用或权限隔离。
- M5：补充 Docker Compose 与新环境复现说明。远程 LLM 凭据只存在后端环境配置，不提交仓库。

## 17. Acceptance Criteria

| 里程碑 | 退出条件 |
|---|---|
| M0 | 数据来源/版本、开发与封存测试样本、证据映射规则及评测分母已冻结；Qdrant 原生全文 BM25 与远程/本地模型完成最小能力检查；100 元预算方案基于单题成本可执行。 |
| M1 | 固定 PDF 和 Markdown 可上传、索引、单轮问答并定位原文；重传无重复、替换/删除后旧内容不可检索；失败导入不显示可用；Dense Baseline 输出逐题记录。 |
| M2 | Dense-only、Hybrid、Hybrid+Rerank 可在同批 Chunk 与冻结输入上重复运行；分别输出文章级/片段级检索结果、时延及错误案例。 |
| M3 | 至少一组人工审查样本证明第二跳利用第一跳新事实；预算/重复/无新证据停止、拒答和引用校验通过；SSE 正常/错误路径有可辨终态，页面展示引用及轨迹；A–E 实际效果与 D/E 相近预算对照、费用和误差分析可复核。 |
| M4 [后续] | 多轮追问、长历史、话题切换及暂态重置回归通过；会话清理与独立 Memory 评测可复核。 |
| M5 [后续] | 新环境可依文档及 Docker Compose 启动并运行评测；Demo 与公开描述只陈述已实现且实测的能力。 |

工程完成和效果提升分开验收：M3 不以预设提升百分比为门槛；若最终未优于 Baseline，报告须说明失败类型，简历不得声称提升。

## 18. Deferred Features

- **M4**：会话级短期记忆、完整历史与 Checkpointer、近期窗口、滚动摘要、追问改写、会话新建/切换/删除及独立 Memory 评测。
- **M5**：Docker Compose、完整 README/架构与 Demo 复盘，以及已交付 SSE 体验和 UI 的进一步打磨。
- **未承诺阶段**：中文文档与问题支持、文档版本历史；须另行定义评测和交付条件，不能自动并入 M3。
- **非目标**：Multi-Agent、GraphRAG、跨会话长期语义记忆、多租户权限体系、OCR、复杂 Office/表格/图片处理、联网搜索、自动同步及生产级分布式平台。

**阶段关口**：具体模型、Chunk 参数、文档替换原子性、BM25/RRF/Reranker 参数、Agent 结构化输出和 SSE 断连/重试协议仍按 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) 解决。本规格只固定可观察行为和边界，不提前给出函数签名或数据库表定义。
