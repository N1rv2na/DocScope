# DocScope 项目上下文

> 状态：已确认的产品边界与术语；下述能力均为待实现目标。完整阶段验收见 [design.md](design.md)。

## 背景与目的

企业技术知识分散在多份文档中。事实问答、跨文档比较和依赖中间事实的分析，需要能追溯来源的回答。DocScope 计划以单 Agent 的有界多跳检索，展示从文档导入到引用、评测的完整 Agentic RAG 路径；项目用途是秋招作品集，不定位为生产级企业知识平台。

## 目标用户与场景

目标用户是研究人员、软件工程师及其他分析技术资料的知识工作者。展示版面向本地部署的单个使用者，只对英文文档和英文问题验收。

- 从文本型 PDF、Markdown 中定位事实并查看原文来源。
- 汇总多份文档，回答跨文档比较问题。
- 先检索出中间实体或事实，再决定下一次查询，回答真正依赖前跳证据的问题。
- 材料不足时明确拒答，不编造引用。
- **M4 后续场景**：在同一会话内追问，并在长历史中控制上下文长度。

## 交付范围

| 阶段 | 范围 |
|---|---|
| M1 基础闭环 | 英文文本型 PDF/Markdown 的上传、状态、重传替换和删除；Dense 索引与单轮问答；可定位引用；基础 Web 与 Dense 基线评测 |
| M3 秋招展示版 | 同批 Chunk 的 BM25 + Dense + RRF、Reranking、证据驱动的有界多跳 Agent、拒答、SSE 与简要轨迹；公平对照和误差分析 |
| M4/M5 后续 | 会话级短期记忆、多轮会话、长对话压缩；Docker Compose、完整交付说明与体验完善 |

M1 只是最早可运行成果。M3 的工程完成不预设效果优于单轮 RAG；提升主张只依据封存测试集的实测结果。远程 LLM 使用外部 Magpie `group/docscope-free`；不设项目级累计金额上限，仍记录 Token、调用量与实际费用，并保留单次运行的有界执行约束。参见 [ADR 0005](adr/0005-llm-route-and-cost-observability.md)。

## 非目标

Multi-Agent、GraphRAG、跨会话长期记忆、多租户权限体系、扫描件 OCR、复杂 Office/表格/图片解析、实时联网搜索、自动企业同步、生产级高并发和复杂管理后台都不进入展示版。中文文档与问题支持、文档版本历史也不在 M3 验收范围内。

## 领域语言

**文档（Document）**：一份可重传替换的逻辑源文件，或作为评测语料的一篇来源文章；系统为其分配可追溯身份。_避免_：把一次上传动作或一个 Chunk 称为“文档”。

**Chunk**：从文档中切出的可索引、可引用片段，保留所属文档与源位置。_避免_：用“文章命中”代替“Chunk 命中”。

**证据（Evidence）**：某次问答实际检索并纳入判断的 Chunk，连同其来源信息。会话摘要不构成文档证据。

**引用（Citation）**：答案中指向已检索证据的可验证引用；引用 ID 存在与引用内容支持结论是两项不同的要求。

**检索轮次（Retrieval Round）**：Agent 基于当前问题和已有证据发起的一次检索；后续轮次应能说明新增查询目标。

**问答运行（Run）**：处理一个独立问题的完整执行，含检索轨迹、停止原因、答案或拒答；以 `run_id` 追踪。

**会话（Conversation）[M4]**：同一使用者的一组相关问答轮次；会话历史用于理解追问意图，不能替代文档事实证据。

**拒答（Abstention）**：必要事实缺失或检索预算耗尽而无法支持确定结论时，明确说明证据不足。

**基础闭环（M1）**：上传 → 索引 → Dense 检索 → 回答 → 引用 → 基线评测的最早可运行成果。_避免_：称其为已完成的 Agentic RAG 展示版。

**展示版（M3）**：完成 Hybrid、有界动态多跳、公平评测与 SSE 的秋招交付门槛。_避免_：把 M4 Memory 当作 M3 已实现能力。
