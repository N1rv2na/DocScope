# DOCS-024 — 实现有界重试与模型调用异常恢复

**Status:** ready-for-agent
**Priority:** P0

## Background

当前模型请求禁用 SDK 自动重试，偶发超时、临时服务错误或可恢复的输出异常会直接终止 Agent Run。现有两次模型调用预算覆盖 Planner 和 Answer，直接增加重试可能突破既有调用上限并破坏评测可比性。

## Goal

建立按错误类型执行的有界恢复机制，在不破坏调用预算、拒答及引用安全的前提下降低可恢复运行错误。

## Scope

- 为超时、临时服务错误、输出截断及可恢复格式异常定义有限恢复策略。
- 区分逻辑模型阶段与实际 LLM 请求次数，记录每次恢复尝试。
- 对认证错误、配置错误、上下文限制及不可恢复错误保持明确失败。
- 保证 Agent Run 与 SSE 路径的恢复行为和最终结果一致。

## Out of Scope

无限重试、自动切换底层模型或渠道、跨 Run 恢复、检索重试和证据策略调整。

## Technical Approach

基于 DOCS-022 的错误分类及 DOCS-023 的输出配置实现受控恢复。建议每个 Run 最多允许一次额外模型请求，并明确更新实际请求预算与评测合同。每次重试重新验证输出结构和引用，不将非法部分结果作为成功回答。

## Implementation Steps

1. 定义可恢复错误、重试条件和总请求预算。
2. 实现有界恢复及调用次数、Token、耗时记录。
3. 覆盖恢复成功、恢复失败和预算耗尽场景。

## Acceptance Criteria

- [ ] 可恢复错误最多触发配置允许的额外请求，不出现无限循环。
- [ ] 不可恢复错误不会被自动重试。
- [ ] Run Trace 区分逻辑阶段、实际请求次数、重试原因和最终结果。
- [ ] 模型输出恢复后仍通过完整 Schema、证据来源及引用 ID 校验。
- [ ] HTTP/SSE 路径在恢复成功、失败和预算耗尽时具有一致的终态语义。
- [ ] 新增调用与 Token 成本被记录，不继续将超出原预算的运行描述为相同调用预算。

## Tests & Validation

超时、HTTP 429/5xx、截断、非法 JSON、认证失败及预算耗尽的故障注入与 API/SSE 回归。

## Dependencies

- DOCS-023 — 优化 LLM 输出预算与结构化输出可靠性
- DOCS-025 — 修正 Agent 提前拒答与停止条件

## Deliverables

有界模型调用恢复机制、实际请求预算记录、故障测试及 API/SSE 回归。
