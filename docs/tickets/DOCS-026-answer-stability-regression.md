# DOCS-026 — 建立回答稳定性回归评测

**Status:** ready-for-agent
**Priority:** P0

## Background

DOCS-016 的固定 dev 子集已记录 14/70 次运行错误及 15/45 次错误拒答。LLM 输出、异常恢复和 Agent 控制流调整后，需要验证稳定性是否改善，同时防止有效拒答、引用安全和调用成本发生隐性退化。

## Goal

建立可复现的回答稳定性回归评测，量化 DOCS-022～025 的修复效果、剩余失败及额外成本。

## Scope

- 复用 DOCS-015/016 的冻结 dev 子集与历史结果。
- 统计运行错误类型、输出截断、格式成功率、正确/错误拒答及核心答案语义正确率。
- 记录实际模型请求、Token、延迟、重试和已知费用。
- 对历史失败案例进行针对性重放，核查引用与停止行为。
- 保存版本化配置、逐题结果、失败分析和对照报告。

## Out of Scope

Cross-Encoder 调优、第二跳合并策略消融、全量新 Benchmark、封存 test 调参和未经核验的效果提升结论。

## Technical Approach

沿用现有评测数据合同和标签隔离。保留原始 v3 结果不变，生成独立版本的回归产物。自动化故障测试与真实模型评测分别报告；模型渠道无法识别、预算变化或样本较小时明确披露可比性限制。

## Implementation Steps

1. 固定回归配置、指标分母与历史对照规则。
2. 执行异常注入和 Agent/API/SSE 回归测试。
3. 重放历史错误样本并开展固定 dev 子集真实模型验证。
4. 汇总稳定性、语义质量、调用成本与剩余问题。

## Acceptance Criteria

- [ ] 历史 14 个错误题次均有对应错误归因或可复核的未确定原因。
- [ ] 回归报告分别统计运行成功率、截断率、格式错误率、错误拒答率和核心语义正确率。
- [ ] 适当拒答、引用合法性及已审核支持性不被混同为同一指标。
- [ ] 实际调用次数、Token、延迟及可获得费用可追溯，重试开销单独披露。
- [ ] 修复前后配置、预算及模型渠道差异被明确记录，不将非严格配对结果解释为因果提升。
- [ ] 测试包含无证据、动态第二跳、异常恢复和 Web Agent 路径；未消除的失败如实保留。

## Tests & Validation

冻结配置核查、指标分母测试、故障注入、真实模型固定样本回归和逐题结果复核。

## Dependencies

- DOCS-023 — 优化 LLM 输出预算与结构化输出可靠性
- DOCS-024 — 实现有界重试与模型调用异常恢复
- DOCS-025 — 修正 Agent 提前拒答与停止条件

## Deliverables

固定稳定性回归配置、自动化测试、逐题结果与修复前后对照报告。
