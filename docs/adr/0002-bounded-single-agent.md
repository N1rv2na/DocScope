# ADR 0002：单 Agent 有界证据驱动检索

状态：Accepted（设计决策；尚未实现）<br>
依据：[design.md §4.2、§6.3](../design.md)、审查决策 Q1、Q2、Q8。

## Context

项目亮点是后续查询能利用前一跳新发现的事实。一次性拆出多条查询只能证明多查询检索，不能证明动态多跳。没有明确停止条件的循环又会放大延迟和远程 LLM 费用。M3 是秋招展示版完成线，远程调用总费用上限为 100 元人民币。

## Decision

M3 使用一个 LangGraph Agent：规划缺失事实 → 调用独立的 Retrieval Engine → 更新带来源的证据 → 评估是否继续或回答。程序强制检索/模型/上下文预算、重复查询与无新证据停止、引用 ID 合法性；LLM 评估必要事实的覆盖及下一跳目标。预算耗尽而必要事实仍缺失时拒答，并记录原因。人工审查的依赖型样本必须能从轨迹看出第二跳利用了第一跳的新事实。

## Alternatives

- **一次性并行拆解查询**：易控制，但无法验证前跳证据驱动后续检索；保留为等预算对照组。
- **只用程序规则判断证据充分**：稳定、易测试，但对复杂问题的事实覆盖过于僵硬。
- **完全交给 LLM 决定继续/停止**：灵活，却难以约束调用预算、无意义循环和不存在的引用。
- **Multi-Agent 协作**：增加协调与评测成本，不属于展示版目标。

## Consequences

- Agent 与 Retrieval Engine 的职责分离；后者不决定是否继续检索，前者不直接操作索引。
- 每轮须保存查询、返回证据、缺失事实和停止原因，便于审查真实动态行为。
- LLM 的充分性判断仍可能错误；须以拒答、错误拒答、引用支持性和依赖型样本检验，而不预设效果提升。
- 具体结构化输出、轮数和阈值仍待 M3 验证，不由本 ADR 固定。
